# /cc-day NN D — 一天的陪跑

参数：周次 `NN`、天 `D`（0–5）。任务卡路径：`outputs/1_cc_coaching/weekNN_<slug>/03_TASK_CARDS/dayD.md`。

## 1. 进入检查

- 任务卡不存在：提示先运行 `/cc-build-week NN`，停止。
- 读 `memory/cc/01_STATE.md` 与 `03_EVIDENCE_LOG.md`：前一天（或前一周 Gate）的证据是否存在且状态不是 `FAIL-*` 未闭合。缺失时不出新卡，先说明需要补哪条证据；用户明确要求跳过时记录“受控跳过”再继续。
- 确认用户今天的环境（5070Ti / V100 / 其他）与可用时间。可用时间小于卡的估时时，按卡内“可裁剪项”裁剪，不砍主要产物。

## 2. Readiness（5 分钟，A0）

从本周 `04_ORAL_EXAM.md` 的 Recall/Explain 层选 2 题，与今天卡相关。用户闭卷口头/文字回答。只记录“能/不能独立回答”，不打分，不展示答案。

## 3. 出卡

原样呈现任务卡内容（不要改写成更抽象的描述）。补充：今天的 AI 辅助等级要求，以及哪些步骤是 `可直接执行`、哪些是 `模板`。

## 4. 执行期间

用户卡住时按 Socratic 顺序：复述现象 → 要求给一个不变量 → 给最小提示 → 让用户提出区分两个假设的实验。除非用户明确要求，不直接给完整修复。

用户从公司环境提问时，先确认摘要不含路径、模型名、原始数字或图像；若不确定，让用户改写后再继续。

## 5. 证据回看

用户提交证据后走 `/cc-evidence` 流程（可直接在本会话内完成）：派 `cc-evidence-coach` 分类，主会话写入 `memory/cc/evidence/YYYY-MM-DD_wNN_dD_<slug>.json` 并在 `03_EVIDENCE_LOG.md` 追加一行。

## 6. 收口

- 更新 `memory/cc/01_STATE.md`：当前天、状态、唯一下一步（明天的卡或今天的回归项）。
- 在 `01_PROGRESS.md` 追加一条简短 `[cc]` 记录（输入：Week NN Day D；输出：证据状态；下一步）。

## 原则

- 一天只推进一张卡；用户提前完成想继续时，先做当日证据归档，再出下一张。
- 不因为“时间到了”把没跑通的步骤标记为完成。

# Workflow 03：公司单向环境安全工作法

## 允许进入公司的准备包

仅在公司政策和审批允许时准备：公开源码及许可证、公开数据清单、合成数据生成器、锁定依赖清单、空白配置、空白报告/schema、hash 清单和离线 README。

任何下载、介质、镜像或安装方式均遵循公司流程；本 workflow 不提供绕过控制的方法。

## 公司内执行

1. 现场运行环境探针，输出留在公司机器。
2. 对输入包计算 hash，与公开准备记录比对。
3. 将 run 目录、数据、日志、trace、checkpoint、图像和 profiler 文件全部指向公司批准的内部位置。
4. 终端摘要也默认留在公司；只有公司明确允许时，用户才可手工写出不含敏感信息的抽象学习总结。
5. 异常诊断优先使用本机报告和空白故障树，不上传原始内容给外部服务。

## 严禁导出

- 代码 diff、配置、日志、loss 曲线、trace、checkpoint、图片或数据样本；
- 真实机器拓扑、利用率、带宽、吞吐、模型/客户名和路径；
- 截图、压缩包、网盘、邮件、聊天附件、外部 API 输入；
- 能由多个“看似匿名”字段重新识别内部系统的组合摘要。

## 个人公开复现

公开作品必须在个人 5070 Ti 或租用环境中，使用公开数据、独立拉取的公开代码和重新产生的日志/图表。只复用抽象实验方法和空模板，不复用公司原始结果，也不暗示两者等价。

## 教练可接收的最小摘要

仅当公司允许时，可用泛化标签描述：

```text
status: PASS | FAIL-MODEL | FAIL-SYSTEM | INCONCLUSIVE
failure_class: data | numeric | memory | communication | checkpoint | evaluation
symptom_summary: 不含路径、模型名、数字或图像的抽象描述
checks_already_done: 公共方法名称
```

若不确定摘要是否合规，不发送；在公司内自行使用教程的决策树。

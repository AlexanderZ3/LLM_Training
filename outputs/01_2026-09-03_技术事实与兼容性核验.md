# 14 周课程技术事实与兼容性核验

> 核验日期：2026-09-03  
> 目的：把会变化的外部事实与用户环境假设分开。  
> 注意：网页核验不能替代用户机器的 environment probe，也不代表教程命令已经运行。

## 1. 结论摘要

本次发现并处理了四个必须显式分支的兼容点：

1. **V100 支持 FP16，不是“不支持 FP16”**；其 Tensor Core 路径以 FP16 为核心，训练需关注 loss scaling。V100 不应默认使用 BF16/TF32/FP8。
2. **CUDA 13 不再为 Volta 提供离线编译和库支持**；公司 V100 环境若显示 13.x，先停在探针与管理员确认，不自行重装。
3. **nanoVLM current main 已从早期 222M 教学路径变化到 450M，并经历 breaking changes**；Week 02 固定 `v0.1 + 222M`，不能把 current main 与旧 checkpoint 混用。
4. **当前 LeRobot/SmolVLA 文档与公司 PyTorch 2.1 不是天然兼容保证**；Week 10 必须先锁 commit、审依赖、跑只读 forward，再决定使用官方入口还是 surrogate。

## 3. 现场仍未知

以下不能从互联网推断：

- 公司实际 V100 型号、每卡显存、8 卡可见性、SM、NVLink/PCIe/NUMA/NIC 拓扑；
- 驱动、CUDA toolkit/runtime、cuDNN、NCCL 与 PyTorch build 的真实组合；
- 公司是否允许联网、git/hf 下载、pip 源、TensorBoard 端口、编译扩展或容器；
- 个人 5070 Ti 当前驱动与 PyTorch wheel 是否完整支持该卡；
- 用户每周真实时间、Task-P 最终选择、数据许可和 H100 预算；
- 任一 loss、吞吐、显存、scale、成功率或算法收益。

因此教程用 `预期观察`、`目标阈值` 和 `停止条件`，不会使用“已通过”措辞。

## 4. 使用时的版本规则

每个第三方项目至少固定：

```text
repository URL
commit or release tag
model revision
dataset revision/config
processor/tokenizer revision
Python / torch / CUDA / key package versions
local patch list and fallback backend
```

如果 current 文档命令与固定 commit 不一致，以固定 commit 的 README、源码 CLI `--help` 和最小 dry run 为准；记录差异，不通过 `strict=False`、`ignore_mismatched_sizes` 或整套升级静默绕过。
